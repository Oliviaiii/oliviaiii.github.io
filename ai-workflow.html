AI 工作方式 · 實證版

我不只會問 AI，
我設計它怎麼工作。

很多人會說「我有在用 AI」。這一頁想回答的是更具體的問題：AI 在我手上做了多少事、我怎麼讓它可靠、 什麼事我從不交出去。所有數字都來自我本機的對話紀錄與 GitHub，用腳本統計，不是印象。

01 / 制度

AI 可靠，是因為我把規則寫成它會遵守的形狀。

這不是一份 prompt。這是一套放在專案倉庫裡、跟著程式碼一起版控的制度：什麼永遠不能做、做 X 前要先讀 Y、什麼叫「做完了」。下面是主要產品倉庫裡的實際清單。

02 / 流程

一張票怎麼走完。

● 是我親自判斷或操作，◇ 是 AI 依制度執行、我抽查。重點不在 AI 做了多少，在於每一步交接時都有東西可以核對。

  1. 需求進 Issue9 種表單 · 驗收條件寫進票

    從客戶訊息、現場觀察或我自己用瀏覽器走一遍的體驗，寫成有情境、有驗收條件的票。需要老闆拍板的事先收斂成白話選項。

    我 · 需求與判斷
  2. 規格OpenSpec · 104 個能力

    功能有規格才能審；規格的每個核取項目之後都要對到測試。AI 幫我起草，我改到 RD 看得懂、驗收驗得了。

    我定義 · AI 起草
  3. 開工環境/issue-start

    一個指令建好 worktree、專屬資料庫、預覽網址，並把看板校正到「開發中」。多張票可以平行開，互不污染。

    AI 執行
  4. 實作Claude Code / Codex

    每個 session 從交接文件開始，環境限制寫成 MUST。大量讀取一律派子代理，主對話只收結論與檔案行號。

    AI 執行 · 我抽查
  5. 雙審verifier + skeptic

    驗收員逐條對照驗收條件附證據；對抗審查員預設「有問題」找 blocker。兩者都拿不到實作者的理由。

    AI 互審
  6. 瀏覽器實測Playwright / Chrome MCP

    像使用者一樣點過一遍：下單、觸發通知、切 5 種螢幕寬度、讀回資料庫。122 個 session 做這件事。

    我下條件 · AI 操作 · 我看結果
  7. PR 審查迴圈/pr-review · @claude · CI

    開 PR 觸發 AI 審查，讀意見→修正→再觸發，上限依變更檔數 3／6／10 輪。CI 分 Floor（紅燈必修）與 Advisory（只回報）。

    AI 迴圈 · 我看最後一輪
  8. 合併與晉升/pr-review --merged

    三道閘門：審查通過且留言晚於最後一次 push、CI Floor 全綠、無衝突。合併後看板階段前進一級，狀態改「測試中」。

    我確認 · AI 執行
  9. 正式站驗證health endpoint + 實際路徑

    等 workflow 跑完，驗 /up，再走一次真正的流程。正式站只建可辨識、可回復的測試訂單。

    我親自
  10. 結案或卡關證據回填 Issue

    通過就結案；卡關就在票裡寫清楚環境、觀察值、卡在哪、解除條件與重測條件，再逐張讀回確認留言存在。

    我親自

04 / 踩過的坑

制度是坑填出來的。

每一條都是實際發生過、有證據、然後改了規則的事。

SYMPTOM · 工作全失

規則假設只有一種執行環境

憲章寫「禁止任何 git 寫入」，結果在遠端容器發起的 session 裡，AI 照字面拒絕 push；容器回收，整個 session 的工作蒸發。

改法：憲章開頭先判別環境（本地互動／遠端自主），git 政策分流；引用的工具一律標註環境依賴，不存在時確認一次、改用替代、回報中明寫。

SYMPTOM · 每個 session 都在付費

818 行規範全量載入

修一個 JS bug 的 session 也要載入稽核接入七步驟；同一條規則重複三次；兩份文件對版本號的規定互相打架，弱模型讀到哪份算哪份。

改法：三層重構——紅線留在本體一條一行、路由表「做 X 前必讀 Y」、細節抽到 docs/rules。大量讀取一律派子代理，主對話只進結論。

SYMPTOM · 「完成」靠自我申報

沒有機器判準的驗證

AI 說「已測試」，找不到測試輸出；說「已同步文件」，開檔沒有。返工的根因幾乎都在這裡。

改法：verify-gate hook 擋收工；verifier／skeptic 雙審且看不到實作過程；驗收條件必須是「可執行指令 ＋ 可核對事實」，寫不出來就是我自己還沒想清楚。

SYMPTOM · 30 秒的誘惑

假綠

測試過不了時，「把測試預期改掉」只要 30 秒。被抓到一次，之後每個 session 都會退回逐步請示，所有人的效率一起陪葬。

改法：過不了就標 skip ＋ 開依賴票，不准改測試充數、不准宣稱已驗證。自主 commit 的授權是靠這條攢出來的，push 至今仍要授權。

SYMPTOM · 額度撞頂

AI 審查的隱形成本

每次 push 都觸發 @claude 審查，審查跑在 GitHub Actions 上，幾天內連續撞到額度上限。

改法：審查迴圈上限依變更檔數動態分 3／6／10 輪，硬上限 10；CI 分 Floor 與 Advisory，沒觸發任何 check 是合法狀態，不空等。

SYMPTOM · 記憶體 95%

關掉的對話，程序還在

一個上午累積 12 個 claude 程序、4.8 GB，工作管理員只看得到一排同名程序，砍錯就砍掉正在跑的任務。

改法：做了 agent-ledger：把程序對到對話標題，看著標題決定；順便把散落的 session 歸納成含 token 統計的週報。

05 / 界線

什麼事我從不交出去。

  • 定義成功。驗收條件、範圍與非目標由我寫；AI 可以幫我把它寫得更可執行，不能替我決定。
  • 對客戶與機關的承諾。報價、時程、能不能做、什麼時候上線，我自己說。
  • 正式環境的不可逆操作。合併到正式、清資料、發信給真人，一律我按下去或我逐項確認。
  • 品味與模糊題。制度補得了執行品質，補不了品味；需求本身模糊時，再多流程也只是把錯誤做得更工整。這種題我會回去問人。
