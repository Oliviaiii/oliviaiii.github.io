How I work

AI 加快動作，
證據守住品質。

我使用 Codex、Claude Code 與 Gemini CLI 理解系統、拆解規格、製作原型與審查變更；但每個結論都要回到程式、測試、實際流程與可讀回的狀態。

  1. 01
    先定義成功

    把一句需求寫成可驗收條件、範圍與非目標。

  2. 02
    找到真正原因

    看程式、資料與時間指標，不用感覺猜根因。

  3. 03
    讓交付可追蹤

    用 Issue、PR、測試與決策紀錄把上下文留住。

  4. 04
    用實際流程驗收

    不只看綠燈；重新操作、讀回資料，確認使用者真的走得通。
