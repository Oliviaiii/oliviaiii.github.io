01 / 工作方式

把現場翻成規格，自己把它做出來，然後自己驗收。

四件事我都親手做。AI 讓開發那段快很多，但「什麼算做完」永遠由我定義、由證據決定。

完整制度與數據 →
A · 需求

把現場翻成規格

  • 每月實地跑近百家藥局的 FAE 經驗：從使用者卡住的地方想問題，而不是從功能清單。
  • 需求訪談 → 使用情境 → 操作流程 → 驗收條件，一路寫到可以直接動工。
  • 把 23 張工程子票裡 83 個待決事項收斂成 5 組白話決策，讓老闆 10 分鐘拍板，再逐張回填 Issue。
B · 開發

自己把它做出來

  • CMS 平台：Widget preview-first 編輯器、主題 CSS 系統、效能修正、使用手冊——761 個 commit。
  • B2B 平台：Laravel ＋ React 全端，從 Docker 骨架到 14 個模組——1,172 個 commit、2,804 個測試案例。
  • AI 是結對工程師：我寫規格與驗收條件，它出第一版，我改、我測、我 commit。
C · 交付

讓交付可追蹤

  • 團隊從訊息追需求，改成 GitHub Projects：9 種 Issue 表單、PR 模板、ChangeLog 與版本規範。
  • 設計「階段 × 狀態」雙欄位看板，每張票從開發到正式站的位置一眼可見。
  • 配合 ISO 27001 的文件與稽核；政府專案每季簡報營運、流量與資安改善。
D · 驗收

自己驗收，留下證據

  • 「測過了」不等於「驗收過了」：實際操作瀏覽器走完流程，讀回資料庫與看板狀態。
  • CI 綠燈、tag 推上去、畫面正常，都不足以宣稱通過；每條結論附證據位置。
  • 發版後等 workflow 跑完，再驗正式站 health endpoint 與實際路徑，才結案。

一張票怎麼走完 · 我設計的流程

  1. 需求 → Issue表單化、驗收條件寫進票裡
  2. 規格OpenSpec 能力規格，104 個
  3. 隔離環境worktree ＋ 專屬 DB ＋ 預覽網址
  4. 實作我＋AI 結對：它出第一版，我改、我測、我 commit
  5. 雙審驗收員 ＋ 對抗審查員（獨立上下文）
  6. 瀏覽器實測模擬真人操作，讀回結果
  7. PR 審查迴圈@claude 審查 ＋ CI，上限 3／6／10 輪
  8. 合併與晉升看板階段前進一級，狀態改測試中
  9. 正式站驗證health endpoint ＋ 實際流程
  10. 結案證據回填 Issue，卡關留言說清楚
我親自判斷或操作AI 依制度執行、我抽查

CASE 01 · 0→1

CMS 建站平台轉型

產品負責人／主導 PM · 數位因子 · 2025.06 –

  • 12 站各自維護的客戶網站，整併到同一套平台
  • 30→7 天需求到網站上線
  • −70%內部回報與客服工單
  • 761個 commit：Blade／CSS／JS／PHP，第二大貢獻者

情境

過去二十年「一案一站」，每個客戶是獨立專案，維護成本隨站數線性成長，需求到上線要一個月。

我做的

  • 定義多租戶平台範圍（多網域、多語系、多規格），把客製需求收斂成可設定的功能。
  • 自己寫：三欄式 Widget preview-first 編輯器（#879，103 個 commit）、主題 CSS 系統重寫、進頁 HTML 3.03 MB → 1.34 MB 的效能修正、77 檔使用手冊。
  • 建立 GitHub Projects 需求／Bug／發版流程，導入 OpenSpec 規格與 AI 開發憲章。
  • 自己做 SEO／GSC 索引診斷、效能量測（找出商品頁 TTFB 1.5–3 秒的根因）、瀏覽器驗收。
  • Laravel
  • 多租戶
  • GitHub Projects
  • OpenSpec
  • ISO 27001

CASE 02 · 上線

B2B 供貨 SaaS（LINE 生態）

產品負責人 ＋ 主要開發者 · 數位因子 · 2026.05 –

  • 1,172個 commit（全 repo 的 91%），Laravel ＋ React 全端
  • 2,804個 Pest 測試案例、140 個 migration、14 個模組規格
  • 5 種螢幕寬度逐一驗收，7 條深連結租戶隔離檢查

情境

供應商與商家之間的訂貨平台，入口在 LINE（LIFF）。通知、砍價改單、階梯價、簽收流程都要在手機上第一次就走得完。

我做的

  • 從 Docker 骨架開始寫到 M1–M14 模組：訂單（代客建單、配送派工、三種現場簽收）、金流回調防護（逾時／冪等／權威金額）、LINE 憑證每日巡檢、官方網站。
  • 把「第一次使用也走得完」寫成規則：前台禁工程術語、禁原生對話框、手機禁橫向捲動，共 80 多條記憶規範給 AI 遵守。
  • 每個新功能先用瀏覽器實際下單、觸發 LINE 通知逐一調整，再發到測試站；發版後驗 health endpoint 與實際路徑。
  • 寫了一個工具自動錄教學影片（旁白＋字幕），功能改版重錄只要一行指令。
  • LINE LIFF
  • Inertia / React
  • UI 準則
  • 教學影片自動化
